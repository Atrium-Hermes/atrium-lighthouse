## Invoke decision
`auto_invoke: true` and the top pick clears the cap, so I queued a rental request at
`.pending-atrium/generate-playwright-tests.json`. It was **not** executed this run —
`ATRIUM_PRIVATE_KEY` isn't in the environment.

To make auto-invoke actually fire, opened a PR wiring the wallet key into the
post-process step (secure pattern — key never touches the Claude step):
- `scripts/postprocess-atrium.sh` — consumes `.pending-atrium/*.json`, re-checks the
  cap, skips already-rented, runs `atrium invoke`, stashes the body under
  `memory/atrium/rented/<slug>.md`. No-ops gracefully if the key is unset.
- `.gitignore` — ignores `.pending-atrium/`.
- `skills/atrium-scout/SKILL.md` — step 4 now writes a pending request instead of
  spending inline.

The PR does **not** edit `aeon.yml` — the bot token lacks `workflows` permission, so
GitHub rejects workflow changes from the App. The operator must apply that one edit by
hand.

**Operator action to go live (3 steps):**
